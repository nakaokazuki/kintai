================================================================================
  勤怠システム　システム概要・仕様書（クライアント向け）
================================================================================
作成目的：本システムの「何ができるか」「どう使うか」「運用上の注意」を、
          専門知識がなくても読める形でまとめたものです。


--------------------------------------------------------------------------------
1. このシステムは何か
--------------------------------------------------------------------------------

社員の「いつ出勤・退勤したか」「休憩は取ったか」を、スマートフォンやパソコンの
ブラウザ（インターネットでページを見るソフト）から記録・確認するための仕組みです。

・社員 … 自分の出退勤を記録し、月の終わりに提出する
・管理者 … 全員の状況を見て、修正・承認・CSVで書き出す

紙のタイムカードやExcelの代わりに、Web上で勤怠を管理します。


--------------------------------------------------------------------------------
2. 主な登場人物とログイン方法
--------------------------------------------------------------------------------

【社員】
  ・社員番号（4桁の数字）を入力して「確認」を押す
  ・デモ環境では 1001〜1100 が登録されている
  ・タブを閉じても、同じ端末・同じブラウザなら社員番号は残りやすい

【管理者】
  ・打刻画面の「管理者」からパスワードで入る
  ・初期パスワード例：7777（本番では変更を推奨）
  ・忘れた場合は「リセットコード」でパスワード再設定できる
    （初期例：RESET-KINTAI-2026）


--------------------------------------------------------------------------------
3. 社員ができること
--------------------------------------------------------------------------------

（1）打刻（出勤・退勤・休憩）
  ・出勤 … 1日1回
  ・退勤 … 1日1回（出勤したあと）
  ・休憩開始／休憩終了 … 出勤中なら複数回できる
  ・ボタンを押すと「記録中」の表示が出る
    → 「記録完了」が出てからタブを閉じると、記録が残ったとみてよい

（2）月次一覧
  ・その月の日付ごとの出勤・退勤・休憩・残業・状態を一覧で見る
  ・未提出／差戻しのあいだは、理由を書いて自分で修正保存できる
  ・平日の未入力日は「未入力／有給／欠勤」を選べる（有給・欠勤にした日は時刻入力なし）
  ・「今日より先の日付」は出ない（未来の月を開くと空に見える）

（3）提出
  ・月の勤怠を「これで確定」として管理者に渡す操作
  ・いつでも提出できる（日付制限なし）
  ・未入力（出勤または退勤が欠けている営業日）があると提出できない
  ・休憩不足は警告のみで、提出自体は止めない
  ・提出後は本人は修正できない → 管理者へ依頼

日付の表示は「2026/9/9」のように「年/月/日」で統一しています。


--------------------------------------------------------------------------------
4. 管理者ができること
--------------------------------------------------------------------------------

（1）ダッシュボード
  ・対象月・対象日を選んで、次を人数や件数で把握する
    - 未提出（対象月）
    - 承認待ち（対象月・提出済みでまだ承認していない）
    - 未入力（対象日を選ぶとその日の人数／「選択なし」なら対象月の合計件数）
    - 休憩不足（同上）
  ・有給・欠勤の日は未入力・休憩不足の集計から除外する
  ・カードを押すと、該当する社員一覧が出る
  ・氏名を押すとその人の勤怠詳細へ進む

（2）勤怠詳細（社員ごと・月ごと）
  ・出退勤や休憩の修正
  ・平日は「未入力／有給／欠勤」を設定できる
  ・1ヶ月分の承認／差戻し
  ・修正・差戻しには理由が必要（あとから履歴で追える）

（3）社員管理
  ・社員の追加・無効化
  ・氏名クリックで勤怠詳細へ

（4）変更履歴
  ・誰が・いつ・何を・どう変えたかを一覧・検索

（5）CSV出力
  ・ダッシュボードで選んだ対象月だけを書き出す（他の月は含まれない）
  ・ボタン表示も「CSV出力（2026/4）」のように、出力対象の月が分かる
  ・ファイル名の例：kintai_2026-04.csv
  ・表計算ソフト（Excelなど）で開ける形式。集計や保管用


--------------------------------------------------------------------------------
5. 勤怠の計算ルール（業務仕様）
--------------------------------------------------------------------------------

【定時】
  10:00〜19:00 を基準にしています。

【残業】
  退勤時刻が 19:00 を超えた分数を残業とします。
  （例：19:30退勤 → 残業30分）

【出退勤】
  ・出勤・退勤はそれぞれ1日1回まで
  ・土日・祝日は原則「休日」表示
  ・休日に働いた場合は、管理者が「勤務した日」として扱える

【有給・欠勤】
  ・平日の日区分として「有給」「欠勤」を設定できる
  ・有給・欠勤の日は出勤・退勤・休憩の入力は不要
  ・残日数管理や半休・申請フローは対象外（区分の記録まで）

【休憩の目安（法令に近い判定）】
  労働時間（出勤〜退勤から休憩を引いた時間）に対して：
  ・6時間以下 … 必要休憩なし
  ・6時間超〜8時間以下 … 必要45分
  ・8時間超 … 必要60分
  足りない場合は画面で「休憩不足」と警告します。
  ※警告でも提出は可能です。

【提出のタイミング】
  ・いつでも提出できる（日付制限なし）
  ・ただし未入力（出勤または退勤が欠けている営業日）があると提出できない


--------------------------------------------------------------------------------
6. ステータスの意味（月の状態）
--------------------------------------------------------------------------------

  未提出   … まだ提出していない。本人が修正できる
  差戻し   … 管理者が差し戻した。本人が直して再提出できる
  提出済み … 本人が提出した。管理者の承認待ち。本人は修正不可
  承認済み … 管理者が承認した。確定扱い


--------------------------------------------------------------------------------
7. データの保管について（消えにくくする仕組み）
--------------------------------------------------------------------------------

本システムはインターネット上のサーバーで動かします。

【重要】
  無料のサーバーだけだと、更新のたびにデータが消えることがあります。
  そのため、勤怠・社員データは別の「データベース（データの倉庫）」に保存します。

  ・アプリの置き場 … Render（レンダー）などのWeb公開サービス
  ・データの倉庫 … Neon（ネオン）などのPostgreSQLという種類のデータベース

  正しくつなぐと、アプリを更新しても社員・勤怠データは残りやすくなります。

【注意】
  ・データベースのプロジェクト自体を消すとデータも消えます
  ・デモデータを強制的に入れ直す操作をすると上書きされます
  ・「絶対に何があっても消えない」わけではないため、重要な月はCSV保存も推奨です


--------------------------------------------------------------------------------
8. 使い勝手に関する注意（無料枠）
--------------------------------------------------------------------------------

・しばらく使わないとサーバーが「休眠」し、次に開くと数十秒〜数分かかることがある
  （故障ではなく、無料プランによくある動きです）
・通信が遅いときは、打刻・確認・月次一覧の初回表示が遅くなることがある
・打刻は「記録完了」を見てからタブを閉じる
・提出は「提出しました」と出てから閉じ、月次一覧で「提出済み」を確認する

9. 画面構成（わかりやすい対応表）
--------------------------------------------------------------------------------

  社員向け
    打刻画面     … 出勤・退勤・休憩
    月次一覧     … その月の一覧・自分での修正
    提出         … 月次の確定提出

  管理者向け
    ダッシュボード … 全体の状況
    社員管理       … 社員の登録・無効化
    勤怠詳細       … 個人の月次修正・承認
    変更履歴       … 修正の記録
    CSV出力        … 対象月の勤怠データの書き出し

10. 用語集（出てきた専門用語の解説）
--------------------------------------------------------------------------------

ブラウザ
  Chrome、Safari、Edgeなど、Webページを見るアプリのこと。

URL
  サイトの住所（例：https://…….onrender.com）。社員に共有するリンク。

サーバー
  インターネット上でシステムを動かしているコンピュータ側のこと。

データベース（DB）
  社員名・出退勤時刻などを整理して保管する「データの倉庫」。

PostgreSQL（ポストグレエスキューエル）
  データベースの種類（製品）のひとつ。本システムでは Neon 上で利用。

Neon（ネオン）
  インターネット上でPostgreSQLを借りられるサービス。データ永続化に使用。

Render（レンダー）
  Webアプリをインターネットに公開するサービス。本システムの画面側を配置。

デプロイ
  プログラムの新しい版をサーバーに載せて公開すること。

再デプロイ
  もう一度デプロイすること。コード修正を反映するときに行う。

セッション
  「今ログインしている人は誰か」をサーバーが一時的に覚えておく仕組み。

Cookie（クッキー）
  ブラウザがサイトごとに覚えている小さな情報。ログイン維持などに使う。

localStorage（ローカルストレージ）
  ブラウザの中に、その端末だけ社員番号などを残す仕組み。
  タブを閉じても番号を残すために使用。

API
  画面とサーバーがデータをやり取りするための窓口。
  （利用者は意識しなくてよい内部の仕組み）

CSV
  表形式のテキストファイル。Excelなどで開ける。

KPI
  ここではダッシュボード上の「未提出○人」などの指標のこと。

営業日
  土日・祝日を除いた、通常の勤務対象日。

祝日
  日本の国民の祝日。システムはカレンダーに沿って休日扱いする。

タイムアウト
  処理が長すぎて制限時間に達し、一度失敗すること。
  通信が遅い・初回起動時に起きやすい。開き直すと成功することがある。

スリープ（休眠）／コールドスタート
  無料プランでしばらくアクセスがないとサーバーやDBが休むこと。
  次のアクセスで起こすのに時間がかかる。
